# Serve controller log rotation

## Problem

The API-server Helm deployment already runs a logrotate sidecar when file
logging and retention are enabled. Its generated configuration covers only
`/root/.sky/api_server/server.log`. Consolidated SkyServe controllers write
long-lived logs under `/root/.sky/serve/<service>/controller.log` and pool
controllers use `batch_controller.log`, so those files currently grow without
the chart's retention bound.

## Behavior contract

When `apiService.serveServerLog` and
`apiService.logs.retention.enabled` are both true, the existing sidecar must
apply `apiService.logs.retention.size` and `rotate 1` independently to:

- `/root/.sky/api_server/server.log`
- `/root/.sky/serve/*/controller.log`
- `/root/.sky/serve/*/batch_controller.log`

Rotation must remain safe for processes that keep log file descriptors open,
so all stanzas retain `copytruncate`. Missing service directories and empty
logs must remain harmless through `missingok` and `notifempty`. Replica logs,
launch logs, task YAMLs, and other persisted state are outside this policy.

When either existing feature gate is false, the chart must continue omitting
the sidecar entirely.

## Solution

Add one Serve-specific stanza to the logrotate configuration generated by the
existing sidecar. A distinct stanza keeps API-server and Serve files as
independent rotation groups while sharing the same configured threshold and
retention count. No new chart value or runtime process is needed.

## Alternatives considered

Application-managed rotation would couple retention to every controller
writer and require migration across controller modes. A second sidecar would
duplicate the existing minute loop and volume mount. A recursive wildcard over
all of `/root/.sky/serve/` would also rotate replica and provisioning logs,
which is broader than the observed problem.

## Test plan

Helm unit tests must assert that the enabled sidecar command contains both
Serve controller patterns, the configured size, `rotate 1`, and
`copytruncate`. Existing tests continue covering the two disabled cases.

Render the chart with default values and with a non-default retention size to
verify valid YAML and value propagation. After deployment, force logrotate in
debug mode or lower the threshold in an isolated render, then confirm a Serve
controller log is truncated and one rotated copy is retained without
restarting the controller.

## Rollout and rollback

Ship through the normal overlay image and chart release. A Helm upgrade changes
only the sidecar command. Rollback restores the previous stanza; application
and controller processes do not depend on rotated copies.
