# Design Proposals

This directory contains designs for possible future SkyPilot capabilities.
These documents are not implementation commitments and must not be treated as
descriptions of current behavior.

Each proposal should include:

- a status and last-updated date;
- the problem, goals, and explicit non-goals;
- a proposed user-facing contract;
- component and data ownership boundaries;
- security, recovery, and compatibility considerations;
- an incremental implementation plan; and
- unresolved questions.

Use snake_case filenames. Keep rejected proposals when their rationale remains
useful, and mark them `rejected` rather than deleting them. Once a proposal is
implemented, mark it `implemented` and move durable architecture documentation
to the parent `sky/design_docs` directory when appropriate.
